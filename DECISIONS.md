# Decisions

One line each: decision, reason.

- Laravel 13 on PHP 8.4 (portable build at `C:\Users\natan\tools\php84`), not the XAMPP PHP 8.2: the spec asks for the latest stable Laravel and PHP 8.3+, and Laravel 13 requires PHP 8.3.
- Local development runs on MySQL 8.0 from Laragon (database `logbook`); the XAMPP MariaDB on the dev machine does not start (InnoDB redo log error) and holds unrelated databases, so it was left untouched. Phases 1–7 were built on SQLite before Laragon was available. Tests default to in-memory SQLite and also pass on MySQL (`logbook_test`); code stays driver-agnostic (driver-specific SQL only in `StatsService`).
- Removed Laravel's Vite/Tailwind scaffold and the Boost `AGENTS.md`/`CLAUDE.md` from `backend`: the backend serves only the API and Filament (which ships its own assets), and the spec does not use Boost.
- No `composer dev` script: Laravel 13's `artisan dev` needs Node tooling in the backend; the README runs `artisan serve` and `queue:work` in two terminals instead.
- Added `NEXT_PUBLIC_SITE_URL` to the frontend env: metadata, sitemap and robots need the public origin.
- Frontend formatting uses Prettier with `eslint-config-prettier`; backend formatting uses Pint (`composer lint` / `composer format`).
- Two services beyond the spec list: `MediaService` (image variants and payloads) and `RevalidationService` (API cache + frontend revalidation); both are needed by the spec's media and caching rules.
- Undated published trips are numbered after dated ones, in creation order: the seeded trips keep the listed order until real dates are entered.
- API cache uses one version counter: any content change bumps it and invalidates every cached response. Simple and safe for a single-author site.
- API throttle is 300 requests/minute per IP: `next build` fetches every page from one server IP.
- Image variants: WebP plus AVIF (when GD supports it, `MEDIA_AVIF`) at 480/800/1200/1600/2400, never upscaled; duplicate widths are dropped from `srcset`; the API adds `avif_srcset` next to the spec's fields.
- Variant files are named after the conversion (`webp-800.webp`) so original file names (often a timestamp) never become public; originals live on the private `originals` disk.
- Photos whose variants are not generated yet are left out of the API, and a cover is `null`, until the queue worker finishes.
- Added the setting key `portrait_photo`: the about page needs a portrait and the spec's key list has none.
- Settings photos are processed outside the media library (the settings table has string keys): variants plus a `meta.json` payload go to `public/site/<name>/`.
- Planned trips return 404 on `/trips/{slug}`; they appear only in `/map` and `/next-rides`.
- Child tables (stops, photos, videos, garage items) have no timestamps: the spec lists timestamps only for trips.
- Days on the road: inclusive date range; a missing end date counts as one day; undated trips add none. Provinces are counted case- and whitespace-insensitively.
- Parameterless GET endpoints use single-action controllers without Form Requests (nothing to validate); the slug is constrained by the route pattern.
- Seeded stops carry their province (a geographic fact, needed for the provinces stat). The planned example uses two stops named "Contoh titik awal/akhir".
- Frontend revalidation tags: trip, stop, photo and video changes send `trips` + `site` (the site payload carries total km); garage sends `garage`; settings send `site`. The job is unique per tag set until processed and waits 3 s, so one trip save with many stops sends one request.
- Media changes revalidate when their last conversion (`lqip`) completes, so the site updates only once images are ready.
- `app:create-admin` requires a password of at least 12 characters, asked twice; running it again changes the password. Only the user whose email equals `ADMIN_EMAIL` may enter the panel.
- Coordinates and YouTube links are validated through small Laravel rule classes (`App\Rules`) that call `CoordinateService` / `YoutubeService`, keeping Filament resources as configuration.
- The Filament dashboard keeps only the account widget (the Filament info widget links to Filament's own site).
- Livewire's temporary upload limit is raised to 25 MB (`config/livewire.php`) to match the spec; production PHP needs `upload_max_filesize`/`post_max_size` of at least 30M.
- Settings photo uploads preview their public 480px variant in the admin (custom `getUploadedFileUsing`); originals are never given a URL.
- Admin delete notifications say "Dihapus" to keep the verb pairs consistent ("Simpan"/"Tersimpan", "Publikasikan"/"Dipublikasikan").
- The photo/video "stop" select lists the trip's saved stops; new stops appear after the trip is saved (helper text says so).
- `RevalidateFrontend` has `uniqueFor = 60`: without it a lost job leaves its uniqueness lock behind and that tag set stops revalidating (found while testing).
- The frontend revalidates tags with `{ expire: 0 }`: the next visit after a change waits for fresh data instead of serving stale content once.
- Pages are prerendered from the API at build time, so `next build` needs the backend reachable; a failing list fetch fails the build instead of shipping empty pages. The layout alone falls back to the env site name if `/site` is down.
- Ledger filters are server-rendered links (`?tahun=2025&medan=pantai`), so they work without JavaScript; `/trip` is therefore rendered per request (data fetches stay cached).
- Ledger rows are full-bleed (rules run edge to edge); a `--inset` token lines their content up with the 1600px column.
- The LQIP shows as a pixel mosaic (`image-rendering: pixelated` on the picture background) rather than a blur, which the anti-template list forbids.
- Keyboard focus on a ledger row uses the yellow focus style; the chapter color is the hover state.
- Undated trips show no year or km in the ledger (the cells stay empty, with screen-reader text).
- Chapter title fit: the server sizes the line in CSS from Archivo 900's real glyph advances (`lib/fit/archivo-900.json`, extracted with fontTools) and container query units; the JS fit-text then corrects small differences after fonts load. Measured CLS on a chapter: 0.
- The cover sits under the data row as the chapter's first photo (full-bleed when landscape, 7 columns when portrait); it is the LCP image and loads eagerly.
- The pull quote sits after the middle stop (after the story text when there are no stops), on a band in the chapter color so it reads as full width.
- The data row needs no labels: units carry the meaning ("612,5 km", "2.093 m", "3 hari"); screen readers get hidden `<dt>` labels. On phones each fact is its own ruled row.
- The kilometer post's cap (chapter color) shows the stop's order along the route; a missing km marker shows "–".
- Landscape photos cycle full-bleed, 8 columns left, 8 columns right; portraits alternate 5 columns left/right with the caption beside, bottom-aligned. The cycle runs across the whole chapter.
- The YouTube facade starts playback after the visitor's click (`autoplay=1` on the iframe that the click creates); nothing loads from YouTube's player before that.
- Stop notes render after the kilometer post as the stop's text; the trip description is the opening text before the first stop.
- Map base data: Natural Earth 10m admin-1 filtered to Indonesia, simplified to 45% with mapshaper (130 KB TopoJSON, 33 provinces); the command is in the README.
- The map engine draws land once in a Mercator projection fitted to the visible trips and pans/zooms with a transform; routes are re-projected into screen space each frame so the 6px asphalt and the 10/14 dash keep their size at every zoom.
- One mask (dash offset on a `pathLength=1` copy of the route) reveals asphalt and center line together; one-stop trips show only their stop and position marker until more stops are added.
- Zoom never goes past the point where a third of the map's short side covers the trip, so a one-stop trip keeps its surroundings.
- Home tour: the map is CSS-sticky and each trip is a real step in the page (headings and "Buka cerita" links stay in the document); ScrollTrigger eases the projection when a step crosses the middle. The overview step comes first.
- Reduced-motion and low-end layouts are chosen before first paint: a tiny head script sets `data-lowend` (same test as `useLowEnd`) and `data-opening` (first home visit of the session), and CSS switches on them, so there is no layout shift.
- Opening skip listens to pointer, key (except Tab), wheel and touchmove; the session flag is written when the sequence completes or is skipped, so an interrupted (unmounted) opening plays again.
- The black screen "gives way" by closing to a horizontal line (clip-path inset to 50%), like a road's center line, while the odometer flies (GSAP Flip, scale mode) into the nav readout, whose cells use the same proportions.
- `/peta`: plain wheel scrolls the page; Ctrl/⌘ + wheel (and trackpad pinch), the +/− buttons, or two fingers zoom; one finger scrolls on touch. Otherwise a full-viewport map would trap scrolling above the text list.
- `/peta` keeps planned trips visible (dashed) regardless of the year scrubber, which only reveals published trips in their numbered order. Each route is a keyboard-focusable button; the text list below reuses the ledger.
- Builds reuse Next's fetch cache in `.next/cache`; delete `.next/cache/fetch-cache` before a build if prerendered pages must reflect data changed since the last build (a running site is kept fresh by the revalidate webhook).
- Ride mode progress is mapped straight from the story's scroll position (ScrollTrigger `onUpdate`, linear). The gauge shows on screens 1024px and wider; narrower screens get the 96px route strip pinned under the nav instead. Under reduced motion both show the finished trip.
- On wide screens the route rail is sticky in columns 9–12 beside text that stays in columns 2–8; full-bleed and right-hand photos and the pull quote pass over it, because photos are the loudest content.
- The ghosts behind the previous/next links are server-rendered SVG paths (d3-geo on the server), so they cost no JavaScript; one-stop neighbours have no ghost.
- Velocity width: one root CSS variable (`--wdth`) for every `data-flex-width` element; scrolling down condenses towards 62, up widens towards 125, idle returns to 100. Their heights are locked at wdth 100 so the reflow never moves the page (no CLS from scrolling).
- The WebGL ledger preview loads its textures through a same-origin Next rewrite (`/media/*` → backend `/storage/*`): WebGL needs CORS-clean images and `artisan serve` sends no CORS headers for static files.
- The WebGL preview is off under reduced motion as well as on touch and low-end devices; with reduced motion on a desktop the rows are plain links with the hover color. Tap-to-expand is for touch and low-end devices.
- The ledger preview is enabled only on `/trip`; `/peta` reuses the ledger as its text list without loading `three`.
- Garage "brand": the data model has no brand column, so the brand goes in the part name or the note; the table shows part, category, install date and note.
- Garage hotspot detail opens beside its square on screens 768px and wider (to the left when the square sits in the right 45%), and under the photo on phones; focus moves to the detail and returns to the square on close or Escape.
- Statistics facts read as "number + plain label" rows ("612,5 kilometer ditempuh"); a missing highest point shows "–". Years without dates are left out of the km-per-year bars, with a hint when no trip is dated yet.
- Next ride draws its dashed routes once on load (the shared route draw), instantly under reduced motion; the about page has no motion besides the page transition.
- The about page shows the bike name as a link to the garage and the YouTube/Instagram links as plain sentences.
- While the mobile menu is open, `main` and the footer are `inert`, so keyboard focus cannot wander behind the full-screen list.
- The page-transition cover reveals itself after 6 s even if navigation stalls, so a slow or failed navigation never leaves the page covered.
- `robots.txt` disallows `/api/` and `/media/` (the image proxy); the sitemap lists the fixed pages and every published trip with its cover image.
- Fonts are self-hosted with `next/font/local`: Archivo and Newsreader variable fonts (OFL) subset to Latin and limited to the axis ranges in use (Archivo wght 500–900 with the full wdth 62–125; Newsreader wght 400–700, opsz 14–28). Only Archivo (76 KB) is preloaded; Newsreader loads when story text needs it. Before: 370 KB of preloaded font files.
- Ride mode (map engine, d3, gauge) loads with `next/dynamic` after the chapter renders; a placeholder holds the strip's exact space, so it causes no layout shift.
- `experimental.inlineCss` was tried and dropped: it improved FCP under applied throttling but lowered the default (simulated) Lighthouse score on the 30-photo chapter from 85–89 to 75–78, because the CSS is also duplicated into the RSC payload.
- `MEDIA_URL` (optional) sets the public base URL of image variants, for a CDN or a separate static host; it defaults to `APP_URL/storage`.
- Section 11 measurements (production build on the dev machine, chapter page with 30 photos, mobile): Lighthouse performance 85, 89 and 86 in three default (simulated) runs; accessibility, best practices and SEO 100. CLS 0 on every page at 360/768/1280/1920 px (404 page: 0.012). JS for `/trip/[slug]`: about 225 KB gzipped, no `three` (the 181 KB `three` chunk loads only on `/trip`, after a hover). Real-device LCP with 4x CPU and Lighthouse's network profile: 1.3 s.
- Known gap: the simulated score swings between runs here (75–89) because `php artisan serve` is single-threaded and the machine runs several servers at once; measure again on the production host. With applied throttling (`--throttling-method=devtools`) the same page scored 83–91.
- Section 13 checklist: admin create/edit/publish with stops, photos and YouTube reaches the site without a redeploy (feature test plus a manual queue-to-revalidate run); all section 5 routes exist with one motion moment each; the forbidden-list grep is clean (the only gradient is the spec's 404 chevron band); reduced-motion and low-end modes switch before first paint; public images carry no EXIF/GPS (test); backend tests (SQLite and MySQL), `tsc`, lint and `next build` pass; the README covers run, build and deploy.
